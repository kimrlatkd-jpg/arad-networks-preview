연결의 안쪽

작업의 경계를,
전송 대기열까지.

AMLI는 작업별 논리 경로와 하드웨어 전송 대기열을 연계합니다. 작업의 시작과 종료, 학습과 추론의 트래픽 특성을 네트워크 자원 관리에 반영하는 구조입니다.

AMLI분리된 세 경로의 예시
  1. 01

    AI 작업

    학습·추론·데이터 이동의 통신 요구를 구분합니다.

  2. 02

    논리 경로

    작업에 맞는 네트워크 영역과 VRF를 구성합니다.

  3. 03

    전송 대기열

    논리 경로를 스위치의 하드웨어 큐와 연계합니다.

  4. 04

    연산과 평가

    데이터 이동과 연산 대기의 변화를 함께 측정합니다.

작업별 VRF·하드웨어 큐 연계 개념. 지원 범위와 성능 효과는 구성별로 평가합니다.

작업별 논리 분리

통신 경로를 작업 단위로 구분해 동시 실행 환경의 흐름을 다룹니다.

경로와 큐의 연계

스위치의 큐 지원 범위와 매핑 방식을 기준으로 전송 구조를 정합니다.

할당과 회수

작업 시작과 종료에 맞춰 경로·대기열 자원을 관리합니다.

추론 경로

응답 지연이 중요한 추론 트래픽의 요구를 별도로 반영합니다.

함께 정하는 과정

효과는,
같은 조건에서 비교합니다.

AMLI의 성능 효과는 검증 중입니다. 실제 워크로드와 네트워크 구성을 기준으로 평가 범위와 측정 조건을 정하고, 적용 전후의 변화를 비교합니다.

성능 효과 검증 중

  1. 01

    워크로드를 정합니다

    데이터 크기, 통신 패턴과 동시 실행 조건을 정리합니다.

  2. 02

    구성 조건을 고정합니다

    스위치·토폴로지·큐 설정과 비교 구간을 일치시킵니다.

  3. 03

    운영 목표에 맞춰 읽습니다

    처리량·지연·연산 대기를 함께 보고 적용 의미를 판단합니다.

자주 묻는 질문

평가 전에
알아둘 내용.

기존 이더넷 환경에서도 검토할 수 있나요?+

AMLI는 표준 이더넷 기반의 네트워크 층을 다룹니다. 실제 평가는 스위치의 VRF·하드웨어 큐 지원, 토폴로지와 작업 규모를 함께 살펴 범위를 정합니다.

GPU 종류만 알면 평가할 수 있나요?+

GPU 정보와 함께 데이터 이동 패턴, 스위치 구성, 동시 작업 수가 필요합니다. 연산 장비만으로 네트워크의 영향이나 적용 효과를 판단하기는 어렵습니다.

성능 검증은 어디에 초점을 맞추나요?+

작업별 경로와 하드웨어 큐의 연계가 공유 네트워크의 대기·처리량에 주는 영향을 살펴봅니다. 비교할 워크로드와 측정 지표를 먼저 정해 결과를 해석할 수 있는 조건을 만듭니다.
